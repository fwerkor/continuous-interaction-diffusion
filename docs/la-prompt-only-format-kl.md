# 350M CID prompt-only KL format alignment

This is the prompt-only format-alignment path for the original
LFM2.5-Encoder-350M-Diffusion. It is independent of the legacy
train-language-alignment command, which uses labeled-answer SFT + KL.

## Teacher and student sequence contracts

Frozen teacher input uses its original chat template:

    [Question]
    {prompt}
    [/Question]

    [Answer]
    [MASK] [MASK] ...

Student input follows the CID answer-boundary convention:

    <|startoftext|> {prompt} <|cid_answer|> [MASK] [MASK] ...

The student uses ONE special token for CID answer start. The pretrained
350M embedding table has 65,536 rows but the tokenizer uses 64,402 IDs.
The new token gets the next free token ID (64,402) and its input
embedding initializes to the average of the original answer-prefix
embeddings. The pretrained weight tensor shape does not change.

## Training objective

The content objective is KL(teacher distribution || student distribution)
on corresponding masked Display positions with temperature scaling.

- Random training prompts are sampled from a PROMPT-ONLY dataset. No
  human answer column is loaded or supervised.
- Fully masked positions train format transfer on diverse instructions.
- Partially masked examples are created ONLY from outputs independently
  generated by the frozen native teacher.
- The teacher's own finished draft supplies a discrete termination event.
  The CID EOS is trained with KL(delta_teacher_stop || P_student)
  weighted by termination_weight. This is teacher pseudo-supervision,
  NOT a data set answer or a native closing marker in the student.
- All teacher and student BACKBONE Display inputs remain MASK-only at
  the CID termination position. Student Display logits learn EOS, while
  CID Runtime keeps the structural EOS as logical metadata.

Do not interpret the separate EOS-event KL as an unchanged teacher
softmax distribution over the original native stop sequence: the teacher
uses a DIFFERENT termination protocol. The event is projected into CID
EOS only for the teacher-generated draft boundary.

## Prepare prompt-only examples

    python scripts/prepare_la_prompts.py \
      --input original-instruction-data.jsonl \
      --output prompt-only-train.jsonl

This exporter emits prompt, source, language. It deliberately ignores
the original dataset's answer field. Prepare validation prompts
separately. Optionally, generate additional native teacher drafts:

    CUDA_VISIBLE_DEVICES=1 python scripts/generate_native_teacher_drafts.py \
      --model /path/to/original-350m \
      --data prompt-only-train.jsonl \
      --output teacher-drafts.jsonl \
      --max-examples 1000 --canvas 64

Native teacher decoding and stopping happens OFFLINE. The resulting
draft JSONL contains natural-language answer text but no markers for
the student to learn. No native termination parser is introduced in
CID Runtime.

## Train and checkpoint

    CUDA_VISIBLE_DEVICES=0 python -m cid.cli train-la-format-kl \
      --model /path/to/original-350m \
      --teacher /path/to/original-350m \
      --data prompt-only-train.jsonl \
      --validation-data prompt-only-val.jsonl \
      --teacher-generations teacher-drafts.jsonl \
      --output-dir output/prompt-only-kl \
      --max-steps 30000 --grad-accum 4 \
      --canvas-buckets 64,128,192 \
      --max-prompt-tokens 384 \
      --temperature 2 --pseudo-probability 0.45 \
      --termination-weight 0.1 \
      --save-every 2000

The training manifest includes the objective, source hashes and
configuration. The script records per-step KL losses and periodically
evaluates masked KL on held-out prompts; saves a fully loadable student
Backbone, tokenizer, optimizer and RNG state. A prior run can be resumed
with --resume pointing to a saved la-step-NNNNNNN directory, keeping
every other configuration unchanged.

## Downstream CID Stage A/B and Runtime

Use the aligned model directory as the Stage A/B Backbone and select
--backbone-protocol cid-answer in BOTH training stages. In this mode:

- Stage A/B/Runtime append the CID answer-boundary ID to Prompt IDs.
- The CID logical Display EOS is mapped to MASK before both native
  IdentityPreservingPath and legacy-joint Backbone forwards.
- CID logical EOS, revisions, tool control, and convergence remain CID
  runtime state. The student never uses a native closing marker.

The adapter configuration is saved in checkpoints, and Runtime reads
it. The default protocol is cid, so existing models retain their
prior behavior.

## Validation and limitations

Teacher KL reduction alone does NOT prove language quality, successful
EOS placement, or parallel decoding performance. Evaluate held-out
English and Chinese prompts, executable code and CID tool trajectories.
The aligned Backbone can be used to start CID Stage A/B; existing
CID control heads trained under earlier raw-prompt conditions are NOT
guaranteed compatible without retesting/retraining.

Prior mixed SFT + KL training is left untouched for comparison.
